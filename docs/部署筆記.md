## 二之二、用 clasp 部署（建議做法）

設定完成後，改程式碼不必再開網頁複製貼上。

```bash
clasp.cmd push -f
clasp.cmd redeploy AKfycbyYVxnV5AZtnGkLKf0mqRTqsUmFTXI5NoaREPQYPveaCrAt1oW8JShMaZjEos6J5NVr-Q -d "改了什麼"
```

`redeploy` 沿用同一組部署 ID，**API 網址不會變**，前端不用改。

| 注意事項 | 說明 |
|---|---|
| Windows 要用 `clasp.cmd` | 直接打 `clasp` 會被 PowerShell 執行原則擋住（`clasp.ps1` 未簽章） |
| 需先開啟 API 權限 | https://script.google.com/home/usersettings 的「Google Apps Script API」要開啟 |
| 換電腦要重新登入 | `clasp login`（macOS 不用加 `.cmd`） |
| 憑證位置 | `~/.clasprc.json`，不在專案內，已列入 `.gitignore` |
| `push` 會刪除線上多餘檔案 | 線上檔案會被同步成跟 `gas/` 一模一樣 |

## 三、⚠️ 重新部署的正確步驟（手動方式，備用）

改完程式碼後：

1. 右上角 **部署** → **管理部署作業**
2. 找到現有的部署，點右上角**鉛筆圖示（編輯）**
3. 「版本」下拉選 **新增版本**
4. 按 **部署**

**網址不會變，前端不用改。**

### ❌ 絕對不要按「新增部署作業」

那會產生一組**全新的網址**，舊網址雖然還能用但停在舊版本，
你會遇到「程式明明改了卻沒生效」，然後找一個下午。

## 四之二、管理者帳號初始設定（第 3 階段，只做一次）

前兩個步驟都在 **Apps Script 編輯器**裡執行，不是在網頁上。

開啟方式：Google Sheet →上方選單「擴充功能」→「Apps Script」。

### 步驟 1：建立兩個新分頁

1. 編輯器上方有一排小按鈕，中間有一個**函式下拉選單**
2. 選 `setupAdminSheets`
3. 按左邊的 **▷ 執行**
4. 下方「執行紀錄」出現「完成」即成功

會建立 `管理者名單` 與 `回覆範本` 兩個分頁。重複執行是安全的（已存在就略過）。

### 步驟 2：建立你自己的超級管理者帳號

1. 函式下拉選單選 `createSuperAdmin`
2. 按 **▷ 執行**
3. **執行紀錄會印出一組隨機的初始密碼——先複製起來**

```
✔ 已建立管理者帳號
  帳號：j46g629h@gmail.com
  角色：SUPER
  初始密碼：Kd7mQx4pRt9n     ← 複製這一行
```

> ⚠️ 密碼**只會出現這一次**。Sheet 裡只存加密後的雜湊值，查不回來。
> 沒記下來也沒關係：執行 `resetAdminPassword()` 會產生一組新的。

**為什麼密碼是程式隨機產生、不是自己設定的？**
因為 `gas/Setup.js` 會跟著 git 上傳到 GitHub。密碼打在程式碼裡就等於公開貼在網路上。

### 步驟 3：登入並改成自己的密碼

1. 開 https://j46g629h.github.io/kantin_PCI_adidas/admin.html
   （或從首頁最下方的「管理者登入」小字進入）
2. 帳號 `j46g629h@gmail.com` + 剛剛複製的初始密碼
3. 系統會**強制**你設定新密碼：至少 8 個字，要有英文字母和數字
4. 設定完成後就會進入案件列表頁

## 四之三、管理者帳號的維運

| 情況 | 怎麼處理 |
|---|---|
| 忘記密碼 | 編輯器執行 `resetAdminPassword()`（先把裡面的 `ACCOUNT` 改成要重設的帳號），會產生新的隨機密碼並解除鎖定 |
| 連續輸錯被鎖 15 分鐘 | 等 15 分鐘，或用上面那招直接解鎖 |
| 新增其他管理者 | 第 3-5 關做完帳號管理頁之後在網頁上操作；在那之前用 `addAdminAccount()` |
| 停用離職的管理者 | `管理者名單` 分頁把「狀態」改成 `DISABLED`。**不要刪除該列**，否則歷史案件的處理者會對不上 |

**絕對不要手動編輯這兩欄**：`密碼雜湊`、`密碼鹽值`。
改壞了該帳號就永遠登不進去，只能重設密碼。

## 五、踩坑紀錄

> 遇到問題和解法都記在這裡，下次就不用重新查。

| 日期 | 問題 | 解法 |
|---|---|---|
| 2026-08-20 | 改了 API 回傳欄位名稱後，手機上查詢頁「點案件就整個消失」且無任何錯誤訊息 | GitHub Pages 的 `Cache-Control: max-age=600`，瀏覽器會快取舊版 JS 達 10 分鐘，舊程式去讀已不存在的欄位就出錯。已在三個 HTML 的 CSS/JS 引用加上 `?v=` 版本參數——**改前端後務必一起把版本號往上加**；同時前端加上防禦性存取與 try/catch，出錯時顯示訊息而不是空白畫面 |
| 2026-08-18 | GitHub Pages 的資料夾下拉只有 `/(root)` 和 `/docs`，選不到 `/web` | GitHub 的限制，只支援這兩個位置。已把前端檔案（`index.html`、`css/`、`js/`）移到專案根目錄，Pages 設定選 `/(root)`。**前端檔案以後都放根目錄，不要再移到子資料夾。** |
| 2026-08-18 | 用 `curl` 測 POST 出現 `Error 411 Length Required` | curl 跟隨 Apps Script 的轉址時會弄丟標頭，不是程式問題。改用瀏覽器或 Node 的 `fetch` 測試即正常。 |
