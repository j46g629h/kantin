## 二之二、用 clasp 部署（建議做法）

設定完成後，改程式碼不必再開網頁複製貼上。

```bash
clasp.cmd push -f
clasp.cmd redeploy AKfycbyYVxnV5AZtnGkLKf0mqRTqsUmFTXI5NoaREPQYPveaCrAt1oW8JShMaZjEos6J5NVr-Q -d "改了什麼"
```

`redeploy` 沿用同一組部署 ID，**API 網址不會變**，前端不用改。

| 注意事項 | 說明 |
|---|---|
| Windows 要用 `clasp.cmd` | 直接打 `clasp` 會被 PowerShell 執行原則擋住（`clasp.ps1` 未簽章） |
| 需先開啟 API 權限 | https://script.google.com/home/usersettings 的「Google Apps Script API」要開啟 |
| 換電腦要重新登入 | `clasp login`（macOS 不用加 `.cmd`） |
| 憑證位置 | `~/.clasprc.json`，不在專案內，已列入 `.gitignore` |
| `push` 會刪除線上多餘檔案 | 線上檔案會被同步成跟 `gas/` 一模一樣 |

## 四之三、管理者帳號的維運

**第 3-5 關做完之後，日常操作都在網頁上：**
用超級管理者登入 → 案件列表右上角的〔帳號管理〕→ 新增 / 停用 / 啟用 / 重設密碼。
（這個連結只有超級管理者看得到。）

| 情況 | 怎麼處理 |
|---|---|
| 新增管理者 | 帳號管理頁〔新增管理者〕。**初始密碼只顯示一次**，關掉就查不回來（Sheet 裡只存雜湊），忘了就再重設一次 |
| 某人忘記密碼 | 帳號管理頁那一列的〔重設密碼〕。預設是**自己輸入一組**，也可以改選**系統產生隨機密碼**。兩種都會解除登入鎖定、讓他目前的登入立刻失效，並要求他第一次登入就改掉 |
| 有人離職 | 帳號管理頁那一列的〔停用〕。他手上的登入會**立刻**失效，不用等 6 小時 |
| 離職的人回鍋 | 同一列按〔啟用〕，密碼不變 |
| **自己**忘記密碼 / 被鎖住 | 網頁上救不了（不能重設自己）。到 Apps Script 編輯器執行 `resetAdminPassword()`，先把裡面的 `ACCOUNT` 改成你的帳號 |
| 想改某人的名字 | 帳號管理頁那一列的〔改名字〕。對方**不會**被登出，他頁面上的「你好，OOO」下次重新整理就會變。已處理過的案件仍顯示當時的名字（那是稽核紀錄，刻意保留）|
| 想改某人的角色 | 網頁上刻意沒有這個按鈕。要交接超級管理者的話，建一個新的 SUPER、再停用舊的即可 |
| 想看某人現在的密碼是什麼 | **看不到，任何人都看不到**，見下方說明 |

> **自己輸入密碼時，系統會擋掉跟其他管理者重複的那一組**，
> 出現「已經有其他管理者在用這組密碼了」就換一組。
> 它不會告訴你是誰在用——說了的話，這個功能就變成可以拿來猜別人密碼的工具。
>
> 想不到要設什麼就改選「系統產生」，它是 12 個字、猜不到的。

**幾件網頁上會被擋下來的事（這是刻意的）：**

- 不能停用自己 —— 手滑就把自己關在門外
- 不能停用**最後一位啟用中的超級管理者** —— 停掉就沒人進得去帳號管理頁
- 不能重設自己的密碼 —— 要改自己的密碼請用「變更密碼」

### 為什麼看不到別人的密碼

Sheet 存的是加鹽 + SHA-256 迭代 1000 次的結果，**這個運算單向不可逆**——
不是系統不給你看，是連系統自己都算不回去。這是所有正經系統的作法。

想確認「我剛剛的重設有沒有生效」，看那一列的**「密碼最後變更」時間**
（需先執行一次 `migrateAddPasswordChangedAt()`，見下方）。

忘記幫某人設了什麼密碼？重設一次就好，三個點擊的事。

**「待本人自行設定密碼」這個標籤不是錯誤。**
它的意思是「這組密碼是你幫他設的，他還沒換成只有自己知道的」。
你剛幫他重設完，這個標籤本來就該在——
等他自己登入改過密碼之後就會消失。

**絕對不要手動編輯這兩欄**：`密碼雜湊`、`密碼鹽值`。
改壞了該帳號就永遠登不進去，只能重設密碼。

**停用請用網頁，不要直接改 Sheet。**
直接在 `管理者名單` 分頁把「狀態」改成 `DISABLED` 也會生效，
但**不會**作廢對方手上的 token——他在接下來 6 小時內照樣能改案件。
（離職不論用哪種方式都**不要刪除該列**，否則歷史案件的處理者會對不上。）

### 報表要寄給誰

**收件人 = 啟用中的超級管理者 ＋「選項設定」分頁裡的額外名單。**
一般管理者**不會**收到（這是刻意的，見規格 §10）。

**要多寄給一個人**（廠長、秘書…）：到「選項設定」分頁加一列——

| 類型 | 代碼 | 中文顯示 | 印尼文顯示 | 排序 | 啟用 |
|---|---|---|---|---|---|
| `REPORT_TO` | 對方的 **Email 地址** | 用途說明（例如「廠長」）| 可留空 | 1 | ✔ |

⚠️ 這個類型的**「代碼」欄放的是 Email**，跟其他類型不一樣
（其他類型放的是 `LOC_02` 這種識別碼，這裡的識別碼本來就是信箱）。

**不想寄給某人了**：把那一列的「啟用」改成 FALSE，**不要刪掉那一列**——
留著才知道以前寄給誰，日後要恢復也只要改回來。

**兩個帳號填同一個信箱不會收到兩封**，系統會自動去重。
（⚠️ 去重的鍵是 **Email**，不是帳號——兩個帳號填**不同**信箱就是兩份。）

想確認實際會寄給誰：執行 `checkMailSetup()`，它會把收件人清單印出來。

#### 要改某個管理者的 Email：用 app，不要改 Sheet

帳號管理頁每一筆旁邊有〔**編輯資料**〕，可以改**姓名**與 **Email**（改自己的也可以）。

| | app 的〔編輯資料〕 | 直接改 Sheet |
|---|---|---|
| 格式檢查 | ✅ `looksLikeEmail()` 擋掉明顯手誤 | ❌ 打錯照樣存進去 |
| 儲存格格式 | ✅ 走 `setTextCell()`，保證純文字 | ⚠️ 靠 Sheets 自己判斷 |
| 改姓名時同步登入狀態 | ✅ `updateSessionsForAccount()` | ❌ 不會 |

🔴 **Email 打錯字的後果比想像中大：** 收件人會變成 **0 位**，報表**完全不寄**。
它會寫進「錯誤日誌」分頁（`sendToRecipients()` 有防這一手），
但**不會有人收到通知**——因為壞掉的正是通知本身。表現出來就是「信一直沒來」。

⚠️ **只改 Email 的話，直接動 Sheet 技術上是安全的**（登入狀態裡只存
帳號 / 姓名 / 角色，沒有 Email；報表每次寄之前都重新讀 Sheet）。
但下面這四欄**絕對不要**在 Sheet 改：

| 欄位 | 為什麼 |
|---|---|
| **角色**、**狀態** | 🔴 改了**不會作廢對方的登入狀態**。在 Sheet 把某人停用，他手上的 token 6 小時內照樣能改案件、能結案——「停用」等於沒生效（設計約定 14）。要用 app 的按鈕 |
| **帳號** | 那是所有查找的鍵（`findAdminByAccount`），改了等於換一個人，舊 token 全部對不上 |
| **密碼雜湊 / 鹽值** | 改壞了那個帳號永遠登不進去，而且救不回來（雜湊算不回明文，設計約定 15）|

#### 改完之後怎麼驗（兩步，都在 Apps Script 執行）

| # | 函式 | 驗什麼 |
|---|---|---|
| 1 | `checkMailSetup()` | 印出**實際收件人清單**、檢查寄信額度、試產生信件內容，並寄一封測試信給**執行腳本的 Google 帳號**（不是收件人）|
| 2 | `sendMonthlyReport()` | **真的寄一封月報給收件人清單**。月報「沒事也要寄」，所以就算資料是空的也會送出——這是唯一能確認「那個信箱真的收得到」的方法 |

⚠️ **換到 Hotmail / Outlook / Yahoo 這類外部信箱時，第 2 步不能跳過。**
Apps Script 是從你的 Google 帳號寄出的，外部信箱**很可能丟進垃圾郵件匣**。
收到之後記得把寄件者加入聯絡人或標記「非垃圾郵件」——
否則日報會安靜地躺在垃圾桶裡，而那正是這封信最不該發生的事。

#### 🟡 「日報沒有來」通常不是壞掉

**日報「沒有未處理案件就不寄」**（`gas/Reports.js:44`），這是規格 §10.1 刻意的設計：
每天寄一封「今天沒事」，兩星期後就沒有人會打開它了，
等到真的有事那天，那封信也一樣被忽略。

所以**清完測試資料之後，隔天早上收不到日報是正確的**，不是排程壞了。
（2026-08-29 實際遇到一次，第一反應是「是不是寄信有問題」。）

**怎麼分辨「沒事所以不寄」與「真的壞了」：**

| # | 去哪看 | 看到什麼就是正常 |
|---|---|---|
| 1 | Apps Script 左側〔**執行項目**〕 | 當天 08:00 有一筆 `sendDailyReport`，狀態「已完成」，紀錄寫著 `目前沒有未處理案件，依規格不寄信。` |
| 2 | `listTriggers()` | 四支排程都在，而且沒有重複安裝 |

⚠️ **反過來說，「日報一直沒來」這件事本身不會有任何警告。**
所以要驗證它真的會寄，唯一的方法是**讓系統裡真的有一筆未處理案件**：

| 步驟 | 做什麼 |
|---|---|
| 1 | 從員工端表單**實際送出一筆**回報 |
| 2 | 執行 **`sendDailyReportNow()`**（不必等到隔天 08:00，這支立刻寄）|
| 3 | 確認信真的到了收件人信箱、內容正確 |
| 4 | 驗完把那筆的「提交識別碼」前面加 `seed-`，跑 6-10 的兩支函式清掉 |

#### 「今日剩餘可寄收件人數：100」是什麼，會不會不夠

那是免費 Google 帳號的每日寄信額度（**100 個收件人 / 天**）。

📌 **這個數字跟員工人數完全無關，11,000 人上線也不會變。**
整套系統只有**三個地方**會寄信：

| 誰寄 | 何時 | 寄給幾個人 |
|---|---|---|
| `sendDailyReport()` | 每天 08:00，**沒有未處理案件就不寄** | 收件人清單（目前 1 位）|
| `sendMonthlyReport()` | 每月 1 日 08:00，一定寄 | 收件人清單 |
| `checkMailSetup()` | 手動執行時 | 1 封給自己 |

**員工送出回報不會寄任何信**（員工端根本沒有收集 Email）。
所以每月用掉的額度大約是「31 天 × 收件人數」，離 100/天 差得很遠。

### 一次性升級腳本

| `migrateAddPasswordChangedAt()` | 在「管理者名單」加上「密碼最後變更時間」欄位 | ✅ 已執行（2026-08-21，第 11 欄）|

**不跑也不會壞。** 這個欄位在程式裡標成「選填」，Sheet 上還沒有的時候

（這是線上事故 1 的正確作法——那次加了欄位就直接部署，導致完全無法登入。）

## 四之五、匯入新一批員工名冊（會做很多次）

> 名冊是**活的**——每個月有新進、有離職。這一段不是一次性的，是常態作業。

### ⚠️ 先做這一件，否則做完要重來

**貼上之前，把工號那一整欄設成「純文字」。**

| 步驟 | 做什麼 |
|---|---|
| 1 | 打開 Google Sheet 的「員工名冊」分頁 |
| 2 | 點欄位標題 **A**（工號欄），選整欄 |
| 3 | 功能表 **格式 → 數值 → 純文字** |

漏掉的話，`0012345` 會被 Sheet 自作主張變成 `12345`，
而那個人**永遠登不進去**——他打自己的工號，系統說「查無此工號」。
更麻煩的是**不會有任何錯誤訊息**，你要等到他來抱怨才會知道。

### 貼上

| 步驟 | 做什麼 |
|---|---|
| 4 | 捲到最後一筆資料的**下一列**（例如原本到第 352 列，就點 A353） |
| 5 | 從來源檔案複製「工號 / 姓名 / 狀態」三欄 |
| 6 | **用「選擇性貼上 → 只貼上值」**（`Ctrl + Shift + V`）|
| 7 | 狀態欄留空也可以，第 9 步會補成 ACTIVE |

⚠️ 第 6 步很重要：直接 `Ctrl + V` 會把來源的**格式**一起帶過來，
可能把你剛設好的「純文字」蓋掉，前導零又沒了。

### 貼完一定要跑這兩支

| 步驟 | 做什麼 |
|---|---|
| 8 | Apps Script → 函式選 **`checkEmployeeRoster`** → 執行 |
| 9 | 如果報告說「狀態空白 N 筆」，再執行 **`normalizeEmployeeStatus`** |

`checkEmployeeRoster()` 會檢查六件事，全部印在執行紀錄上：

| 檢查 | 為什麼重要 |
|---|---|
| 工號被存成「數字」的儲存格 | **前導零已經消失**，那幾個人登不進去 |
| 格式不是「純文字」的儲存格 | 現在還沒壞，但下次編輯就會壞 |
| 工號長度分布 | 突然冒出「5 碼 × 3 筆」通常就是前導零被吃掉的那幾筆 |
| 工號重複 | 兩批名冊有重疊時會發生。同一個人出現兩次不會壞，但統計會怪 |
| 工號 / 姓名空白 | 空白的那一列等於一個沒有人 |
| 狀態欄有沒有奇怪的值 | 只認 `ACTIVE` / `INACTIVE` |

⚠️ **重點看「總筆數」和「工號重複」兩行。**
總筆數應該是「原本的筆數 + 這次貼的筆數」。
對不上就是貼的時候少了或多了幾列。

📌 這支會順手清掉工號查詢的快取，所以**新名冊立刻生效**，
不必等 TTL 過期、不必重新部署。

|---|---|
| ❌ 不用改程式 | 名冊是資料，不是設定 |
| ❌ 不用重新部署 | 後端讀的是 Sheet 的即時內容 |
| ❌ 不用排序 | 查詢用 TextFinder，順序不影響速度 |
| ❌ 不用刪掉離職的人 | 改成 `INACTIVE` 就好——**刪掉的話，他過去的案件會查不到姓名** |

### 6-10　清除測試資料

開發期間用 `seedTestFeedback()` 等函式灌了假回報進去。
不清掉的話，**試辦第一份月報會把假資料算進統計**，而且案件編號不會從 001 開始。

| 步驟 | 做什麼 |
|---|---|
| 1 | 打開 Apps Script 編輯器 |
| 2 | 上方函式下拉選 **`previewTestDataCleanup`** → 按〔執行〕 |
| 3 | 看「執行紀錄」。⚠️ **確認「會留著 N 列」那一行的 N 是 0** |
| 4 | 確認名單裡都是你認得的測試資料 |
| 5 | 改選 **`removeTestFeedbackConfirmed`** → 按〔執行〕 |
| 6 | 執行紀錄會說刪了幾列、丟了幾張照片、計數器怎麼調整 |

⚠️ **第 3 步是整段最重要的一行。**
「會留著 N 列」如果不是 0，代表 Sheet 裡有**不是測試資料**的回報。
那可能是你自己實測時送的真實案件——先確認那是什麼再繼續，
因為**刪掉的是員工寫的東西，回不來**。

📌 判斷依據是「提交識別碼」開頭是不是 `seed-`。
真實提交用的是瀏覽器產生的 UUID，永遠不會長這樣。

#### 🔴 N 不是 0 是**常態**，不是異常

**2026-08-29 實際執行時就是這樣**：試跑掃到 37 列，34 列是 `seed-`，
**3 列不是**（第 16、37、38 列＝`PCI-202608-015 / 016 / 017`）。
那三筆是開發期間**自己用瀏覽器實際送出**的測試案件，
提交識別碼是 `crypto.randomUUID()` 產生的真 UUID，程式當然認不出來。

**只要你曾經打開表單真的送過一次，N 就不會是 0。**

##### 處理方式：改識別碼，**不要手動刪列**

| 步驟 | 做什麼 |
|---|---|
| 1 | 從刪除清單推出「沒被列到」的列號，或直接看「提交識別碼」欄哪幾列不是 `seed-` 開頭 |
| 2 | **先確認那幾列是什麼**（工號 / 姓名 / 內容 / 提交時間）。是自己測的才繼續 |
| 3 | 把那幾列的「提交識別碼」**最前面加上 `seed-`**（`a3f8…` → `seed-a3f8…`），其他欄位一個字都不要動 |
| 4 | 重跑 `previewTestDataCleanup()`，確認「會留著：**0** 列」 |
| 5 | 再執行 `removeTestFeedbackConfirmed()` |

⚠️ **為什麼不能直接在 Sheet 刪那幾列**——兩個後果都不會報錯：

| 手動刪列的後果 | 為什麼 |
|---|---|
| 第一筆真實案件的編號**不會是 001** | 「系統計數」不會跟著改，計數器停在舊數字。2026-08-29 那次若留著 3 列，202608 會停在 17，下一筆變成 `-018` |
| 那幾筆的照片**永遠留在 Drive** | 沒有任何地方記得它們存在，變成孤兒檔案——那正是這種清理功能要消滅的東西 |

📌 改完識別碼重跑試跑時，**「連帶丟進垃圾桶的照片」張數變多是正常的**，
代表那幾列裡也有照片，現在程式會一起處理掉。

📌 照片是**丟垃圾桶**不是永久刪除，30 天內都救得回來。

📌 案件編號的計數器是**照剩下的資料重算**，不是歸零——
歸零會讓下一筆拿到重複的編號，那是回不來的。

#### ✅ 2026-08-29 實際執行結果（已完成）

```
✔ 已刪除 37 列，照片丟進垃圾桶 2 張。
系統計數：移除 11 個月份、更新 0 個月份。
```

「移除 11 個月份、**更新 0 個**」代表 202510～202608 這 11 個月**一筆都不剩**，
所以整列被拿掉而不是改數字——這正是「乾淨到底」該有的樣子。
下一筆真實案件會是 `PCI-YYYYMM-001`。
