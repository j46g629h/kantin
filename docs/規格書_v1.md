# PCI 餐廳回饋系統 — 系統規格書

## 一、系統概述

本系統供 PCI adidas 工廠員工在餐廳用餐時回報問題與建議，管理者透過專用介面進行案件追蹤與回覆，所有資料自動彙整至 Google Sheet。

- 系統名稱：PCI 餐廳回饋系統（PCI Cafeteria Feedback System）
- 使用對象：全廠員工（回報端）、5 位管理者（管理端）
- 介面語言：印尼文 / 中文（可切換）
- 存取方式：員工手機掃 QR Code、管理者電腦瀏覽器
- 技術架構：GitHub Pages（前端）+ Google Apps Script（後端）+ Google Sheet / Drive（資料層）
- 費用：零成本（全部使用 Google 免費服務 + GitHub Pages 免費託管）

---

## 二、系統架構

```
員工（手機）          管理者（電腦）
     |                     |
     ▼                     ▼
┌─────────── GitHub Pages 前端 ───────────┐
│  [回報表單]  [案件查詢]  │  [登入]  [案件管理]  │
└────────────────┬────────────────────────┘
                 │ API 請求
                 ▼
      [Google Apps Script 後端]
          /              \
    [Google Sheet]   [Google Drive]
     - 回報資料        - 圖片資料夾
     - 員工名冊
     - 管理者名單
     - Dashboard
```

資料流向：
1. 員工填寫表單 → 前端打包資料 → 送至 Apps Script API
2. Apps Script 驗證工號 → 產生案件編號 → 寫入 Google Sheet
3. 圖片上傳至 Google Drive 指定資料夾 → Sheet 存圖片連結
4. 管理者透過管理介面查看案件 → 前端向 Apps Script 請求資料 → 回傳顯示
5. 管理者更新狀態/回覆 → 前端送至 Apps Script → 更新 Sheet 對應欄位
6. 每月定時排程 → Apps Script 產出統計 → 寄送 email 給管理者 + 更新 Dashboard 分頁

## 三、Google Sheet 分頁結構

### 3.1 分頁一：回報資料（Feedback Data）

| 欄位名稱 | 欄位代號 | 資料類型 | 說明 |
|---------|---------|---------|------|
| 案件編號 | case_id | 文字 | 格式：PCI-YYYYMM-NNN（自動產生） |
| 提交時間 | submit_time | 日期時間 | 系統自動記錄 |
| 工號 | emp_id | 文字 | 員工輸入，比對名冊驗證 |
| 姓名 | emp_name | 文字 | 比對名冊自動帶入 |
| 餐廳地點 | location | 文字 | 下拉選單：第二餐廳 / 第四餐廳 / R3廠餐廳 / VIP餐廳 |
| 問題分類 | category | 文字 | 下拉選單：菜單口味 / 衛生環境 / 服務態度 / 餐廳設備 / 其他建議 |
| 問題描述 | description | 文字 | 員工自由輸入 |
| 滿意度評分 | rating | 數字 | 1-5 星 |
| 圖片1連結 | image_1 | URL | Google Drive 圖片連結（可為空） |
| 圖片2連結 | image_2 | URL | Google Drive 圖片連結（可為空） |
| 處理狀態 | status | 文字 | 未處理 / 處理中 / 已結案（預設：未處理） |
| 處理者 | handler | 文字 | 管理者姓名（處理時自動帶入） |
| 處理回覆 | response | 文字 | 管理者填寫回覆內容 |
| 處理時間 | response_time | 日期時間 | 管理者回覆時系統自動記錄 |

### 3.2 分頁二：員工名冊（Employee List）

| 欄位名稱 | 資料類型 | 說明 |
|---------|---------|------|
| 工號 | 文字 | 唯一識別碼 |
| 姓名 | 文字 | 員工姓名 |

維護方式：管理者直接在 Google Sheet 手動增刪。

### 3.3 分頁三：管理者名單（Admin List）

| 欄位名稱 | 資料類型 | 說明 |
|---------|---------|------|
| 姓名 | 文字 | 管理者姓名 |
| Email | 文字 | 用於登入驗證 + 月報寄送 |

### 3.4 分頁四：Dashboard 統計

即時更新的統計分頁，包含：
- 各餐廳回報數量統計
- 問題分類佔比
- 處理狀態比例（未處理 / 處理中 / 已結案）
- 各餐廳平均滿意度評分
- 月度趨勢（回報數量、平均評分）
- 平均案件處理時間

## 四、前端頁面規劃

### 4.1 員工端 — 首頁（語言選擇）

- 進入系統後首頁提供語言切換：Bahasa Indonesia / 中文
- 選擇後記住語言偏好（本次使用期間）
- 顯示兩個主要入口按鈕：
  - 提交回報（Lapor Masalah / 提交回報）
  - 查詢案件（Cek Status / 查詢案件）

### 4.2 員工端 — 回報表單頁面

表單欄位（全部必填，圖片除外）：

1. 工號輸入框 — 輸入後即時比對員工名冊，比對成功自動帶入姓名並鎖定，比對失敗顯示錯誤提示
2. 姓名顯示 — 自動帶入，不可編輯
3. 餐廳地點 — 下拉選單（第二餐廳 / 第四餐廳 / R3廠餐廳 / VIP餐廳）
4. 問題分類 — 下拉選單（菜單口味 / 衛生環境 / 服務態度 / 餐廳設備 / 其他建議）
5. 問題描述 — 多行文字輸入框
6. 滿意度評分 — 1-5 星點選
7. 圖片上傳 — 最多 2 張，支援手機相機直接拍照或相簿選取，不壓縮
8. 提交按鈕

提交成功後顯示：
- 成功提示訊息
- 案件編號（如：PCI-202507-001）
- 提醒員工記錄案件編號以便查詢
- 「繼續回報其他問題」按鈕（自動帶入工號和姓名，清空其他欄位）
- 「返回首頁」按鈕

提交失敗時顯示：
- 失敗提示訊息（如：網路連線異常，請稍後重試）
- 「重新提交」按鈕

### 4.3 員工端 — 案件查詢頁面

- 提供兩種查詢方式（擇一輸入）：
  - 輸入案件編號 → 查詢單筆案件
  - 輸入工號 → 查詢該工號所有歷史案件
- 查詢結果顯示：
  - 案件編號
  - 提交時間
  - 餐廳地點
  - 問題分類
  - 問題描述（摘要）
  - 處理狀態（以顏色標示：紅色=未處理、黃色=處理中、綠色=已結案）
  - 管理者回覆內容（已結案的案件）
- 工號查詢結果以列表呈現，點選可展開詳情

### 4.4 管理者端 — 登入頁面

- 輸入 Email 地址
- 比對管理者名單分頁驗證
- 驗證成功進入案件管理頁面，自動記錄登入的管理者姓名
- 驗證失敗顯示錯誤提示

### 4.5 管理者端 — 案件管理列表頁面

- 案件列表顯示所有案件，包含：
  - 案件編號、提交時間、餐廳地點、問題分類、處理狀態
- 篩選功能：
  - 按餐廳地點篩選
  - 按問題分類篩選
  - 按處理狀態篩選（未處理 / 處理中 / 已結案）
  - 按日期範圍篩選
- 排序：預設按提交時間倒序（最新在上）
- 點選案件進入詳情頁面

### 4.6 管理者端 — 案件詳情 / 回覆頁面

顯示完整案件資訊：
- 案件編號、提交時間
- 員工工號、姓名
- 餐廳地點、問題分類
- 問題描述全文
- 滿意度評分
- 圖片（可點擊放大檢視）

管理者操作區域：
- 處理狀態下拉選單（未處理 → 處理中 → 已結案）
- 回覆內容文字輸入框
- 儲存按鈕
- 處理時間由系統自動記錄

## 五、後端 API 規劃

Google Apps Script 提供以下 API 端點（透過 doGet / doPost 處理）：

| API 功能 | 方法 | 用途 |
|---------|------|------|
| 驗證工號 | GET | 前端輸入工號後即時驗證，回傳姓名 |
| 取得選項資料 | GET | 回傳餐廳列表、問題分類列表（方便前端動態載入） |
| 提交回報 | POST | 接收表單資料 + 圖片，寫入 Sheet，圖片存 Drive |
| 查詢案件（案件編號） | GET | 回傳單筆案件詳情 |
| 查詢案件（工號） | GET | 回傳該工號所有案件列表 |
| 管理者登入驗證 | GET | 驗證 email 是否在管理者名單 |
| 取得案件列表 | GET | 管理端用，支援篩選與排序參數 |
| 更新案件狀態 | POST | 管理者更新狀態、填寫回覆 |

## 六、操作流程

### 6.1 員工回報流程

```
手機掃描 QR Code
    ↓
進入系統首頁（選擇語言）
    ↓
選擇「提交回報」
    ↓
輸入工號 → 系統自動比對名冊
    ↓
  ┌─ 比對失敗 → 顯示錯誤，請重新輸入
  └─ 比對成功 → 自動帶入姓名
    ↓
選擇餐廳地點（下拉選單）
    ↓
選擇問題分類（下拉選單）
    ↓
輸入問題描述
    ↓
選擇滿意度評分（1-5 星）
    ↓
上傳圖片（選填，最多 2 張）
    ↓
點擊提交
    ↓
  ┌─ 提交失敗 → 顯示錯誤，可重新提交
  └─ 提交成功 → 顯示案件編號
    ↓
  ┌─ 繼續回報其他問題（帶入工號，清空其餘欄位）
  └─ 返回首頁
```

### 6.2 員工查詢流程

```
進入系統首頁 → 選擇「查詢案件」
    ↓
輸入案件編號或工號
    ↓
顯示查詢結果
    ↓
  ┌─ 案件編號查詢 → 顯示單筆案件詳情與處理進度
  └─ 工號查詢 → 顯示所有歷史案件列表 → 點選查看詳情
```

### 6.3 管理者處理流程

```
瀏覽器輸入管理者介面網址
    ↓
輸入 Email 驗證登入
    ↓
查看案件列表（可篩選/排序）
    ↓
點選案件查看詳情
    ↓
更新處理狀態 + 填寫回覆
    ↓
儲存 → 自動更新 Google Sheet
```

## 七、案件編號規則

格式：`PCI-YYYYMM-NNN`

- PCI：工廠代碼
- YYYYMM：年月（如 202507）
- NNN：當月流水號，從 001 開始遞增

範例：
- 2025 年 7 月第 1 筆：PCI-202507-001
- 2025 年 7 月第 15 筆：PCI-202507-015
- 2025 年 8 月第 1 筆：PCI-202508-001（每月重新計數）

產生邏輯：Apps Script 在收到新回報時，查詢當月已有的最大流水號 +1。

## 八、月報規格

### 8.1 自動寄送 Email

- 頻率：每月 1 日自動執行（統計上個月資料）
- 收件人：管理者名單分頁中所有 email
- 內容包含：
  - 上月回報總數
  - 各餐廳回報數量
  - 問題分類佔比（百分比）
  - 平均滿意度評分（整體 + 各餐廳）
  - 案件處理率（已結案 / 總案件數）
  - 平均處理時間（從提交到結案的天數）
  - 未結案案件清單

### 8.2 Dashboard 分頁

Google Sheet 內建的即時統計分頁，使用公式自動更新：
- 各餐廳回報數量圖表
- 問題分類佔比圓餅圖
- 處理狀態佔比（未處理 / 處理中 / 已結案）
- 各餐廳平均滿意度
- 月度趨勢折線圖
- 平均處理天數
